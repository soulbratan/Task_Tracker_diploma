# Task Tracker System (SkripnikovOV)

Корпоративная система управления задачами с организационной структурой, JWT-аутентификацией и распределением нагрузки между сотрудниками.

---

## Ключевые особенности

### **Организационная структура**
- **Иерархические отделы** с поддержкой неограниченной вложенности
- **Три уровня должностей**: Администратор, Руководитель, Сотрудник
- **Автоматическая синхронизация** данных между пользователями и должностями
- **Строгие бизнес-правила**: не более 2 руководителей в отделе и 4 администраторов во всей системе

### **Управление задачами**
- **Иерархические задачи** с поддержкой подзадач (до 3 уровней вложенности)
- **Интеллектуальное распределение нагрузки** между сотрудниками
- **Анализ блокирующих задач** для выявления узких мест в процессах
- **Автоматическое управление статусами** при назначении/снятии исполнителей

### **Безопасность и доступ**
- **JWT-аутентификация** с access/refresh токенами
- **Детальная система разрешений** на уровне объектов
- **Ролевая модель доступа** с разграничением прав для администраторов, руководителей и сотрудников
- **Валидация сложности паролей** и корректности контактных данных

### **Аналитика и отчетность**
- **Специальные эндпоинты** для анализа загруженности сотрудников
- **Статистика по отделам** и исполнителям
- **Поиск оптимальных исполнителей** для важных задач
- **Email-уведомления** через Celery о назначении задач и регистрации

## Архитектура проекта

### **Модульная структура**
Проект разделен на три независимых, но интегрированных приложения, каждое со своей ответственностью:

#### **1. Приложение `users` - Управление пользователями**
- **Модели**: Кастомная модель User (наследник AbstractBaseUser)
- **Ответственность**: Аутентификация, регистрация, профили пользователей
- **Интеграция**: Синхронизация с должностями из приложения `organization`

#### **2. Приложение `organization` - Организационная структура**
- **Модели**: 
  - `Department` - иерархические отделы компании
  - `Position` - должности с уровнями (администратор, руководитель, сотрудник)
- **Ответственность**: Управление структурой компании, назначение сотрудников на должности
- **Бизнес-правила**: Ограничения на количество руководителей и администраторов

#### **3. Приложение `tasks` - Система управления задачами**
- **Модели**:
  - `Task` - задачи с иерархией и зависимостями
  - `Comment` - комментарии к задачам
- **Ответственность**: Трекинг задач, распределение нагрузки, аналитика
- **Специальные алгоритмы**: Поиск блокирующих задач, подбор исполнителей

### **Взаимодействие между приложениями**
- *Пользователи* назначаются на *должности* (назначет администратор или суперпользователь);
- *Должности* прикреплены к *отделам* (у каждого отдела не более 2-х руководителей);
- *Руководитель* создаёт, получает или распределяет задачи между сотрудниками(должностями);
- *Задачи* назначаются от руководителя сотрудникам своего отдела, либо руководителю нижестоящего отдела.

## Аутентификация и авторизация

Система использует JWT (JSON Web Tokens) для безопасной аутентификации и детальную систему разрешений на основе ролей и должностей.

### JWT Аутентификация

#### **Токены и сроки действия**

| Токен | Назначение | Срок действия | Обновление |
|-------|------------|---------------|------------|
| **Access Token** | Доступ к защищенным эндпоинтам | 60 минут | Через Refresh Token |
| **Refresh Token** | Получение нового Access Token | 7 дней | - |

#### **Эндпоинты аутентификации**

```
POST /api/users/           # Регистрация нового пользователя
POST /api/users/login/     # Вход в систему (получение JWT)
POST /api/users/auth/token/refresh/  # Обновление Access Token
POST /api/users/auth/token/verify/   # Проверка токена
GET  /api/users/me/        # Получение профиля текущего пользователя
```

## Ролевая модель

Система использует трехуровневую ролевую модель, основанную на **должностях в организационной структуре**. Права доступа определяются не статическими ролями, а динамически на основе назначенной сотруднику должности (одна активная должность на пользователя).

### Уровни доступа

| Уровень | Ключ | Максимум | Описание |
|---------|------|----------|----------|
| **Администратор** | `admin` | 4 в системе | Полный доступ ко всем функциям системы |
| **Руководитель** | `manager` | 2 в отделе | Управление своим отделом и подотделами |
| **Сотрудник** | `employee` | Неограниченно | Базовый доступ к своим задачам и профилю |

#### **Характеристики:**

- ✅ Двухэтапное удаление отделов

### Сотрудник (Employee)

#### Общая информация

**Сотрудник** — это базовый уровень доступа в системе. Большинство пользователей являются сотрудниками. Они имеют ограниченный доступ, сосредоточенный на выполнении своих задач и управлении личным профилем.

#### Права доступа по приложениям

#### **Приложение Users**

##### ✅ **Разрешено:**
- **Просмотр профиля**: Доступ к собственному профилю через `/api/users/me/`
- **Редактирование профиля**: Обновление личных данных (имя, фамилия, телефон, фото)
- **Изменение пароля**: Через стандартный механизм смены пароля
- **Просмотр контактных данных**: Только своих данных

##### ❌ **Запрещено:**
- Просмотр профилей других пользователей
- Создание новых пользователей
- Редактирование данных других пользователей
- Изменение системных полей (`is_staff`, `is_active`, `is_superuser`)
- Доступ к списку всех пользователей

#### **Приложение Organization**

##### ✅ **Разрешено:**
- **Просмотр структуры компании**: Доступ к `/api/organization/organization/chart/`
- **Просмотр списка сотрудников**: Доступ к `/api/organization/employees/` (только ФИО, отдел, должность)
- **Просмотр своего отдела**: Информация о текущем отделе и должности
- **Просмотр дерева отделов**: Иерархическая структура компании

##### ❌ **Запрещено:**
- Создание новых отделов
- Редактирование существующих отделов
- Удаление отделов
- Создание/редактирование/удаление должностей
- Назначение сотрудников на должности
- Просмотр детальной информации о других отделах (кроме названия)

##### ❌ **Запрещено:**
- Создание задач для других сотрудников
- Назначение исполнителей
- Редактирование задач других сотрудников
- Удаление задач (кроме собственных в статусе "Создана")
- Доступ к статистике по задачам
- Использование специальных эндпоинтов анализа

### Аутентификация и пользователи (`/api/users/`)

| Метод | Эндпоинт | Описание | Права доступа | Параметры |
|-------|----------|----------|---------------|-----------|

## Бизнес-правила и валидация

Система включает комплексные бизнес-правила, обеспечивающие целостность данных и корректность бизнес-процессов.

### **Правила для пользователей (Users)**

#### **1. Валидация пароля**
```
 Минимальные требования:
 - Длина: не менее 8 символов
 - Заглавные буквы: минимум 1
 - Строчные буквы: минимум 1
 - Цифры: минимум 1
 - Специальные символы: минимум 1
 Пример валидного пароля: "SecurePass123!"
```

#### **2. Уникальность email**

**Основные правила:**
- **Email как первичный идентификатор**: используется для входа в систему
- **Автоматическая нормализация**: все email приводятся к нижнему регистру
- **Запрет дубликатов**: один email - один пользователь
- **Валидация формата**: стандартная валидация Django EmailField

#### **3. Валидация телефона**

```
 - Используется django-phonenumber-field
 - Формат: международный
 - Регион по умолчанию: RU
```

#### **4. Правила для organization**

```
 Иерархия отделов:
 - Отдел не может быть родителем самому себе
 - Запрещены циклические ссылки в иерархии
 - Максимальная глубина не ограничена
 - При удалении отдела:
    - Этап 1: Освобождение всех должностей с сотрудниками
    - Этап 2: Удаление, только если нет дочерних отделов
    
 Администраторы:
 - Максимум 4 администратора во всей системе
 - Автоматически получают is_staff = True
 - При снятии с должности is_staff сбрасывается, если нет других admin-должностей

 Руководители:
 - Максимум 2 руководителя в одном отделе
 - Могут управлять своим отделом и подотделами

 Сотрудники:
 - Неограниченное количество
 - Один сотрудник → одна активная должность
 
 Назначение:
 - Сотрудник может занимать только одну активную должность
 - Назначение может выполнять только администратор или руководитель отдела
 - При смене должности автоматически обновляются поля пользователя
 - При удалении должности сотрудник автоматически снимается
```

#### **5. Правила для задач**

```
 Правила:
 - Максимальная глубина вложенности: 3 уровня
 - Запрещены циклические ссылки
 - Прогресс родительской задачи рассчитывается автоматически
 - При удалении родительской задачи каскадно удаляются подзадачи

 Кто может назначить задачу:
 - Администратор - любому сотруднику
 - Руководитель - сотруднику своего отдела
 - Руководитель - руководителю нижестоящего отдела

 Ограничения:
 - Нельзя назначить задачу сотруднику другого отдела (кроме администратора)
 - Нельзя назначить задачу руководителю вышестоящего отдела
 - Исполнитель может иметь только одну активную задачу одновременно

 Сроки:
 - Дедлайн не может быть в прошлом
 - Дата выполнения (completed_at) автоматически устанавливается при статусе "Выполнена"
 - Задачи без дедлайна считаются бессрочными
 - Просроченные задачи автоматически выделяются в интерфейсе
```
